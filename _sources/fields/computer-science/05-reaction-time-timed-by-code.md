## Core Literature — Read This Before Starting Unit II

Real, verified sources for this project. Read these before Unit II begins — they're what your literature review and hypothesis should be built on.

### 1. Woodworth, R. S., & Schlosberg, H. (1954). Experimental Psychology (Rev. ed.). Holt, Rinehart and Winston.

(Verified in the Physics field's "How Fast Is a Thought?" project.) This classic reference establishes standard reaction-time measurement methodology and typical human reaction-time ranges — the exact reference values the project's self-built tool should be checked against as a validity test.

### 2. Whelan, R. (2008). Effective analysis of reaction time data. The Psychological Record, 58(3), 475-482.

Whelan's paper discusses common pitfalls in analyzing reaction-time data, including how outlier responses (accidental early presses, or moments of inattention producing very slow responses) can distort average results if not handled carefully. This is directly useful for the project's data-analysis step, since a self-built reaction-time tool with real human testers will inevitably collect some noisy, outlier data points.

### 3. Deary, I. J., Der, G., & Ford, G. (2001). Reaction times and intelligence differences: A population-based cohort study. Intelligence, 29(5), 389-399.

This large population study found a modest but real association between simple reaction time and general cognitive ability measures, providing useful, honest context for the project: while reaction time is a genuine measurable brain-processing signal, it should be presented as one narrow indicator, not a broad measure of overall intelligence or ability.

### Unit II — Research Investigation
*Weeks 5–8 · Required artifact: **Research Investigation / Prospectus***

**Process for this unit (same for every project in the chapter):** Week 6 **Prediction Ladder** tournament + Week 7 **Build-a-System** laboratory.

**Steps specific to this project:**

- [ ] **Literature review:** basic explanations of nerve signal timing and reaction time, plus the basic timer/event-handling programming concepts used to build the tool.
- [ ] **Hypothesis:** reaction times measured by the student-built tool will fall within the range reported in published reaction-time research, validating that the homemade tool works correctly; additionally, peers' reaction times will be somewhat slower on a distraction condition (like doing the test while a phone notification sound plays) compared to a no-distraction condition.
- [ ] **Variables:** distraction condition (present vs. absent) as the thing being compared; measured reaction time as the outcome.
- [ ] **Methodology:** test peers under both conditions using the student-built tool, record times, and compare, while also comparing overall results to published reference ranges as a validity check.

## How the Six Outputs Link Into One Portfolio

Every unit of this project is the same original, self-built tool, made more rigorous at each stage. Unit I writes the first working timer. Unit II validates that tool against real published reference ranges, then tests a real distraction hypothesis. Unit III explains that exact original tool and its real results to an audience who's used online reaction-time tests without ever wondering how they're built. Unit IV turns it into a live, interactive demo anyone can try. Unit V asks CS classes to adopt this exact project as their timer/event-handling assignment. A CS mentor sees a student who built, validated, and used their own instrument — not just an app someone else made.
